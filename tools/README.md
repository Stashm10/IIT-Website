# Rebuilding the site

The site is plain static HTML (GitHub Pages). Everything under `data/`, `band/` and
`index.html` is generated by the scripts in this folder.

## What is in `tools/`

| File | Purpose |
|---|---|
| `bands.json` | Band plan: the 10 groups and 91 bands, histogram bins. |
| `reference_2018-01-01.json` | Independent reference values for Jan 1 2018, used by the tests. |
| `build_data.py` | Reads the `.h5` power data, writes `data/index.json` and `data/bands/<id>.json`. |
| `build_settings.py` | Reads receiver settings (HDF5 attributes only), writes `data/settings.json`. |
| `build_site.py` | Writes `index.html` and `band/<id>/index.html` from `templates/`. |
| `spectrum.py` | Shared helpers: day keys, band masks, statistics, fixed-bin histograms. |
| `test_*.py` | Tests (run with pytest). |

`bands.json` and `reference_2018-01-01.json` are read from this folder by default. To use copies
elsewhere, set `IIT_V2_DIR` to the folder that contains them.

## Setup (once)

```bash
python3 -m venv venv
venv/bin/pip install -r tools/requirements.txt
```

## The data folder

The 2018 `.h5` files are not in the repository. Tell the scripts where they are with
`--data-dir PATH` or the `IIT_DATA_DIR` environment variable; without either, the scripts stop with a
one-line message. The files are only ever opened read-only.

```bash
export IIT_DATA_DIR="/path/to/2018 IITSO Wideband Data"
```

## Run order

1. **Power data** (slow the first time, about 20 seconds per day; resumes where it stopped):

   ```bash
   venv/bin/python tools/build_data.py --workers 6
   ```

   - Each day is cached in `tools/cache/<date>.json`; re-running only processes missing days.
   - Files on the same date are pooled into one day; duplicate copies such as `name (1).h5` count once.
   - Files that cannot be opened are skipped and listed in `data/index.json` (`unreadable`).
   - If `bands.json` changes, delete `tools/cache/` and run again.

2. **Receiver settings** (attributes and sweep times only, never the power data; takes seconds and
   does not touch the cache):

   ```bash
   venv/bin/python tools/build_settings.py
   ```

   Writes `data/settings.json`: for each sub-band, the periods of identical settings, every change,
   and any day whose files disagree; plus any file- or session-level attribute that varies.

3. **Pages** (needs step 1; band pages also read `data/settings.json` from step 2):

   ```bash
   python3 tools/build_site.py
   ```

   Edit `tools/templates/*.html` and `assets/*` for layout changes, then re-run this step.
   The notice bar and footer shared by every page are `templates/notice.html` and `templates/footer.html`.

## Tests

```bash
cd tools && ../venv/bin/pytest -q
```

- `test_reference.py` checks Jan 1 2018 against `reference_2018-01-01.json` for all 91 bands. It needs
  the `.h5` files and is skipped (with the reason shown by `pytest -rs`) when `IIT_DATA_DIR` is not set.
- `test_site.py` checks the generated pages (run step 3 first): band limits printed exactly as in
  `bands.json`, and the notice bar and footer on every page.

## How months are combined

Every day stores a histogram on fixed 0.5 dB bins (-150 to +20 dBm). A month, quarter or the whole
year is the exact sum of its days' histograms, so every reading counts equally. The pooled mean, min
and max are exact; the pooled median and percentiles are read off the summed histogram (within the
0.5 dB bin width).
